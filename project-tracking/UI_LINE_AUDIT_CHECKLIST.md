# Checklist ตรวจ UI และระบบ LINE

วันที่เริ่มตรวจ: 16 กันยายน 2569

## วิธีบันทึกผล

- ใช้ `[x]` เมื่อผ่าน, `[ ]` เมื่อยังไม่ตรวจ และ `[!]` ในข้อความประกอบสำหรับรายการที่พบปัญหา
- ทุกปัญหาควรมีหน้าจอ/flow, ขั้นตอนทำซ้ำ, ผลที่ควรได้, ผลจริง และภาพหรือเวลาเกิดเหตุ
- หลังแก้ต้องทดสอบซ้ำบน viewport/อุปกรณ์เดิม และระบุ commit หรือ backend binary ที่แก้

## UI แอป iOS

### พื้นฐานทุกหน้า

- [ ] Light/Dark mode อ่านง่ายและสีสถานะไม่สื่อความหมายผิด
- [ ] Dynamic Type ไม่ตัดข้อความหรือทำปุ่มซ้อนกัน
- [ ] ปุ่มสำคัญมีพื้นที่กดเหมาะสมและไม่ต้องเดาว่ากดค้างได้
- [ ] Loading, empty, error และ offline state แยกกันชัดเจน
- [ ] Keyboard ไม่บังช่องกรอกหรือปุ่มบันทึก
- [ ] การบันทึกไม่ปิดหน้าก่อนข้อมูลลงเครื่องสำเร็จ
- [ ] เปิดซ้ำ/กดซ้ำไม่สร้างข้อมูลซ้ำ

### หน้าและ Flow สำคัญ

- [ ] Login, remembered account, local passcode และ logout
- [ ] สมัครบัญชีและ forgot-password
- [ ] Dashboard: KPI ห้อง/ลูกบ้าน/การเงินตรงกับข้อมูลจริง
- [ ] Dashboard: งานซ่อมทุกสถานะแสดงครบและผลรวมตรงกับรายการ
- [ ] ลูกบ้าน: เพิ่ม แก้ไข จอง เข้าพัก ย้ายห้อง ย้ายออก และสัญญา
- [ ] ห้องและราคา: ห้องซ้ำ ประเภทซ้ำ ห้องมีผู้พัก และการเปลี่ยนราคา
- [ ] การเงิน: สร้างรอบบิล แก้ไข รับบางส่วน รับเต็ม และหลายบิลในเดือนเดียวกัน
- [ ] หลักฐานการโอน: เปิดรูปเต็ม ซูม อนุมัติ และปฏิเสธ
- [ ] ใบเสร็จ: ดู แชร์ บันทึก Photos และ AirPrint
- [ ] งานซ่อม: เปิดรูป แก้รายละเอียด เปลี่ยนทุกสถานะ ค่าใช้จ่าย และช่องทางชำระ
- [ ] Backup/import: ไฟล์ปกติ ไฟล์เสีย คนละบัญชี และข้อมูลซ้ำ
- [ ] Manual sync: success, conflict, offline, retry และข้อมูลจาก LINE

## LIFF — ผูกบัญชีและข้อมูลลูกบ้าน

- [ ] เปิดจาก Rich menu แล้วโหลดภายในเวลาที่เหมาะสม
- [ ] ผู้ยังไม่ผูกเห็นฟอร์มกรอกเบอร์ก่อน และไม่เห็นรายการห้องทั้งหมด
- [ ] เบอร์ไม่พบ/พบหลายห้อง/รูปแบบผิด แสดงข้อความที่เข้าใจง่ายและ fail closed
- [ ] ห้องและชื่อลูกบ้านที่พบถูกต้องก่อนกด “เชื่อมต่อบัญชี”
- [ ] เชื่อมสำเร็จแล้วเปิดซ้ำเห็น “ข้อมูลของฉัน” ไม่กลับไปฟอร์มผูกบัญชี
- [ ] เมื่อแอดมินย้ายห้อง ข้อมูลลูกบ้านเปลี่ยนตามหลัง sync
- [ ] บิลค้างทุกใบเรียงถูกต้องและผูกด้วย stable user ID
- [ ] วันที่ ค.ศ./พ.ศ., วันครบกำหนด และเวลาอัปเดตไม่แปลงซ้ำ
- [ ] ไม่มีเลขบัตรประชาชน เบอร์โทร หรือข้อมูลลับเกินจำเป็นในหน้า LIFF
- [ ] ไม่มี horizontal overflow หรือการขยายหน้ากะทันหันหลังกรอกข้อมูล

## LINE Bot และ Rich menu

### Rich menu

- [ ] ปุ่ม “ผูกบัญชี” เปิด LIFF ที่ถูกต้อง
- [ ] ปุ่ม “การเงิน” ส่งข้อมูลบัญชีที่ผูกอยู่ ไม่อ้างลูกบ้านคนก่อนในห้องเดียวกัน
- [ ] ปุ่ม “แจ้งซ่อม” เริ่ม flow และบันทึกเข้าฐานข้อมูล/snapshot
- [ ] ผู้ที่ยังไม่ผูกบัญชีได้รับคำแนะนำไปผูกบัญชีอย่างชัดเจน

### การเงินและสลิป

- [ ] ใบแจ้งหนี้แสดงเลขบิล ห้อง ชื่อ รอบบิล วันครบกำหนด และเวลาอัปเดตครบ
- [ ] ค่าเช่า น้ำ ไฟ ส่วนกลาง ค่าปรับ ค่าใช้จ่ายเพิ่มเติม ยอดบิล ชำระแล้ว และคงเหลือตรงฐานข้อมูล
- [ ] หลายบิลในเดือนเดียวกันไม่ถูกซ่อนหรือรวมผิด
- [ ] ส่งรูปสลิปแล้วข้อมูลปรากฏในแอปหลัง sync
- [ ] รูปสลิปเปิดได้เฉพาะบัญชีเจ้าของและ URL หมดอายุตามกำหนด
- [ ] ส่งข้อความ/รูปซ้ำไม่สร้างรายการซ้ำโดยไม่ตั้งใจ

### งานซ่อม

- [ ] แจ้งรายละเอียดและส่งรูปแล้วรายการปรากฏในแอปหลัง sync
- [ ] รูปอาการเสียเปิดดูเต็มจอและซูมได้ในแอป
- [ ] เปลี่ยนเป็น “กำลังติดต่อช่าง” แล้ว LINE ได้รับสถานะ
- [ ] งานมีค่าใช้จ่ายเข้าสู่ “รออนุมัติค่าใช้จ่าย” แล้ว LINE ได้รับ Flex ใบเสนอราคาที่มียอด/รายละเอียดถูกต้อง
- [ ] linked resident กดอนุมัติแล้วสถานะเป็น “กำลังซ่อม” และ sync กลับแอป
- [ ] linked resident กดปฏิเสธแล้วกลับ “กำลังติดต่อช่าง”; แอดมินแก้ยอดและส่งใบเสนอราคาใหม่ได้
- [ ] ผู้ใช้ LINE คนอื่น, ผู้พักคนเก่า และ action เก่าถูกปฏิเสธโดยไม่เปลี่ยนข้อมูล
- [ ] งานมีค่าใช้จ่ายเข้าสู่ “รอตรวจสอบชำระเงิน” แล้ว LINE ได้รับ Flex บิลพร้อมปุ่มส่งสลิป
- [ ] ส่งสลิปจากบิลแล้วหลักฐานปรากฏในแอปหลัง sync และผู้ดูแลตรวจรับได้
- [ ] งานไม่มีค่าใช้จ่ายข้าม quote/payment ไป “กำลังซ่อม” และ “เสร็จสิ้น” ได้โดยไม่ส่งบิล
- [ ] ทุก Flex แสดงวันที่แจ้งและเวลาอัปเดตจริงเป็น Asia/Bangkok/พ.ศ. โดยไม่เกิดปี 3112
- [ ] บันทึกสถานะเดิมซ้ำไม่ส่งข้อความซ้ำ
- [ ] ค่าใช้จ่ายและช่องทางชำระที่ส่งกลับ LINE ถูกต้อง

### ความผิดพลาดและความปลอดภัย

- [ ] LINE signature ผิดถูกปฏิเสธ
- [ ] LIFF token ผิด channel/หมดอายุถูกปฏิเสธ
- [ ] ไฟล์ของ tenant อื่นเปิดไม่ได้
- [ ] เมื่อ LINE API ล่มหรือ timeout ข้อมูลหลักยังบันทึกสำเร็จและมีสถานะรอส่งซ้ำ
- [ ] มีหลักฐาน delivery log/retry/idempotency สำหรับข้อความสำคัญ
- [ ] มีนโยบาย opt-out และการหยุดข้อความตามผู้ใช้
